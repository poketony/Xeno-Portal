- 제노사가 본편 3개와 외전 4개를 같은 화면에 배치하고 기존 순서를 유지합니다.

## 이전 구현 상태

- Astro 정적 페이지 23개. 제공된 로고와 스케치의 중앙 상단·각진 소개선·왼쪽/오른쪽/왼쪽 사선 배너를 유지했습니다.
- 제노기어스는 한국닌텐도 작품 페이지의 큰 이미지와 간결한 소개 구성을 참고한 단일 작품 화면입니다. 짧은 소개와 특징을 표시하고, 기존 두 주소에서 같은 화면을 제공합니다.
- 제노사가는 PS2 본편 I·II·III를 큰 소개 블록으로, 프릭스와 파이드 파이퍼·DS·미싱 이어를 본편 사이의 작은 카드로 배치합니다.
- 제노블레이드 메인 배너와 공통 메뉴는 `https://www.nintendo.com/kr/xenoblade/index.html`로 연결합니다.
- 시리즈 화면에서는 “작품 둘러보기” 제목과 검색·필터를 제거했습니다. 기존 전체 검색 주소에서는 한국어·영어·일본어·별칭 검색, 시리즈·기종·분류 필터와 발매일 정렬을 유지합니다.
- 파이드 파이퍼를 포함한 작품 14개와 판본은 구분해 관리합니다. 공식 한국어 지원과 팬 패치 등록 여부도 별도 데이터입니다.
- 실제 패치·SWF는 등록하지 않았습니다. 다운로드 링크가 없는 항목에 다운로드 버튼을 표시하지 않습니다.
- 작품과 자료에서 같은 미싱 이어 감상 화면으로 접근합니다.

## 자동 검증

- `pnpm check`: 오류 0, 경고 0. 빌드로 복사된 외부 Ruffle 코드는 검사에서 제외하며 자체 코드와 Astro 템플릿을 검사합니다.
- `pnpm test`: 6개 통과. 기존 검색·필터·데이터 관계 검사에 제노사가 본편 위계, 외전 위치·발매 순서, 모든 작품의 누락·중복 방지 검사를 추가했습니다.
- `pnpm build`: HTML 23개 정적 생성. 모든 생성 HTML의 내부 링크·이미지·스크립트·대표 주소에서 `/Xeno-Portal/` 기본 경로와 파일 존재를 검사합니다.
- 공식 Ruffle 0.7.1의 JS 청크·WASM 두 파일·라이선스 파일을 전체 복사합니다. 플레이어가 없는 페이지는 Ruffle을 요청하지 않습니다.
- 격리된 검증용 SWF가 생성 HTML에 섞이지 않았는지도 검사합니다.

## Ruffle 통합 검증 — 미싱 이어 원본과 구분

배포 결과물 밖의 `.qa/` 로컬 서버에서 직접 만든 단색 SWF를 사용했습니다. 이 파일은 미싱 이어 원본이 아니며 사이트 콘텐츠나 배포 파일에 포함하지 않습니다.

- 실제 Ruffle 0.7.1 JS와 WASM이 프로젝트 하위 경로에서 로드되고 단색 화면을 렌더링했습니다.
- 일시정지 후 재개 버튼 표시, 재개, 다시 시작 동작을 확인했습니다.
- 전체 화면 진입과 Escape로 종료를 확인했습니다.
- 장을 바꾸면 이전 `ruffle-player`가 DOM에서 제거됨을 확인했습니다.
- 없는 파일의 HTTP 404 안내와 다시 시도 버튼을 확인했습니다.
- SWF가 아닌 HTML 응답의 서명 오류 안내를 확인했습니다.
- 장별 원본 다운로드 허용/숨김 설정이 반영됨을 확인했습니다.
- 장 쿼리 URL의 새로고침과 마지막으로 연 장 버튼 표시를 확인했습니다.

실제 미싱 이어의 한글·일본어, 원본 버튼, 음성·BGM, 장면 전환, 외부 자원, 화면비와 각 장의 호환성은 **원본 미제공으로 미검증**입니다. 단색 SWF의 성공을 원본 호환성의 근거로 삼지 않습니다.

## 배포 상태

- 최초 로컬 구현을 마친 뒤 사용자가 `96a7817` (`초기 빌드`) 커밋을 `main`에 푸시했습니다.
- [초기 GitHub Actions 실행](https://github.com/poketony/Xeno-Portal/actions/runs/41012758951)의 빌드·배포 작업이 모두 성공했습니다. 잠금 파일 설치, 타입 검사, 테스트, 정적 빌드, 아티팩트 업로드, Pages 배포의 개별 성공을 확인했습니다.
- 접속 실패의 원인은 코드나 빌드가 아닌 사용자 지정 도메인 `poketony.xeno.portal`이었습니다. 기본 주소가 해당 HTTP 주소로 301 이동했으며 DNS 조회는 이름 없음으로 응답했습니다.
- 사용자가 기본 주소 복구를 승인한 뒤 Pages의 사용자 지정 도메인 한 항목만 제거했습니다. API 재조회에서 `cname: null`, `build_type: workflow`, `https_enforced: true`와 `https://poketony.github.io/Xeno-Portal/` 주소를 확인했습니다. 저장소 권한·공개 범위·브랜치 보호·원격 주소는 변경하지 않았습니다.
- 실제 공개 메인 화면과 시리즈·작품·감상 페이지, 로고가 HTTPS로 응답하는 것을 확인했습니다. 실제 SWF가 없는 상태의 감상 화면과 구분합니다.
- 운영 주소: **https://poketony.github.io/Xeno-Portal/**. 이후 `main` 푸시에도 같은 워크플로가 배포를 갱신합니다.
